# The UI tree, 2026-11: the plan and what landed

A decision record. In November 2026 every surface of the console moved from
the immediate `ui` verbs (called in `_draw()` every frame) to a UI tree: an
app declares typed state, named actions and its pages once, and one C engine
lays them out, draws, focuses and routes input. How it works now is
`docs/app_api_v1.md` §3 and `native/moy_uitree/README.md`; what the
immediate API was is `docs/history/ui_api_2026-10.md`. This file records why,
what was decided and by whom, and how the plan compares with what is on dev,
audited against origin/dev `e32a8c43d` on 2026-11-27.

The plan was never committed. Its revisions were kept outside the
repository: draft 1 and revision 2 (2026-11-19, with an architecture, a
performance and a durability review folded in), revision 3 (2026-11-20, with
the owner's decisions), the API spec (revision 4, 2026-11-21) with its own
adversarial review, the spike and phase handoffs, and the decision log the
owner's rulings below come from (K1 to K16). The owner's Typora autosaves of
revision 2 from 2026-11-19 end byte-equal to the revision kept; the earlier
ones differ only by the reviews being folded in, so no hand edit of the
owner's survives beyond what revision 2 says.

## 1. Why a tree, and the options that lost

**The cause.** Revision 2 counted 15 re-architectures of the UI in five
months. Every speed lever since the 2026-10 API needed the app's cooperation:
a fast-frame vocabulary (`gen`, `keep`, `held`, `snap`, `wash`) that an app
had to know, and a pass of the app's Python every frame. #243's step 0
(2026-10-30) put about half of the engine pass in the app's Python per verb
call. The interfaces that had held (`.moy`, the verb table, the `v04`
canvas, `board.toml`) each had a spec apart from the code, executable
conformance, a level, and no frame mechanics; the immediate UI API had none
of the four. The tree takes the frame out of the API: no script runs to
produce a frame of engine-drawn content, and the engine is free to be
rewritten under a fixed contract.

**What lost, and when.**

| option | its fate |
|---|---|
| Keep the immediate verbs, tuned (#243's blocks, `docs/history/ui_blocks_2026-10.md`) | revision 2's fallback for a failed G10; not needed. The verbs went from every tier on 2026-11-24 (`476472989`) |
| Stage 1 first: the trims, the idle gate with a blocking sleep, the wallpaper's cover and plane | owner, 2026-11-19: no work that only helps the current UI. The trims were dropped; the gate and the wallpaper were set aside and not taken up |
| A screen described by a `.ui` data file | ran in the spike (7 screens, pixel-equal from Python and C; a 216-line parser). Owner, 2026-11-20 (K1): a build function in every tier, no second format to maintain; a data form may come out of the API later (K2). The blobs compiled ahead of time (L12) are output, not a format anyone writes |
| Build once and mutate by handle (Piu, Slint); a per-row data-source event for lists (Pebble, Playdate) | revision 2's fallbacks for G1/G4 and G6; never needed |
| A pilot on dev beside the old engine, gated G1 to G10, with dev frozen 10 to 15 days for the sweep | replaced by host-first, the whole port at once (K4, 2026-11-20), then the C engine first and apps after (K7). Two bridges replaced the freeze (§3) |

## 4. Gates, targets and the reviews

**The pilot's gates did not run as gates.** K4 and K7 replaced the gated
order, so G1 to G10 never decided anything. What stands in for each:

| gate | as it ended |
|---|---|
| G1, the build in every tier | the conformance fixtures, each in Python, Lua and wasm (`tests/uitree_conformance/`) |
| G2, no script per frame | the traces record every handler run; the engine counts runs a frame (`Engine.calls`, `frame_calls`), but no test pins zero on a scroll, a key step or a theme switch |
| G3, G5, G6 | no measure: neither a tree page's scroll frame, press to glass, nor a thousand-row list is a metric of the perf pass (`docs/perf/ledger.md`) |
| G4, page open | measured on the T-Deck on 2026-11-21 against dev; answered by L12; not a ledger metric |

| G8, memory | `tests/test_uitree_c_memory.py` pins the kept trees on the board model; the Guition S3 runs the on-glass suite with a Lua tree app (`61960452c`) |
| G9, the audit | ran (2026-11-20, every call site by syntax tree); its unmatched list was answered by the kinds the sweep added |
| G10, the owner reads one app in both forms | not run; the app guide's first app is the counter in Python and Lua (`38d6ad73c`) |

**Revision 2's invariants.** I2 (no call answers with tree state), I5 (one
vocabulary generated from one table), I6 (one door: the level and the
fingerprint), I7 (one invalidation mechanism, held by
`tests/test_shift_apps.py`) and I8 (one escape hatch, held by
`tests/test_clean_cut.py`) have their guards. I1's guard is the traces only
(G2 above). I3, handles with a generation, is not built: its code M01 is
reserved and never raised. I4 holds by construction (derives and templates
are the engine's).

**Targets.** Revision 2 predicted a Settings scroll and a window drag on the
Waveshare P4, and a key step, a drag and a page open on the T-Deck, before
and after each stage; the spike measured the engine module's flash. Of those,
only the window drag and the idle desk are metrics of the perf pass
(`docs/perf/ledger.md`), and the engine's flash is a part of each board's
image (`docs/perf/image.md`), larger than the spike's or the board check's
figure: at this audit the P4 boards' headroom was the
thinnest of the consoles.

## 5. Skipped, and why

- **Stage 1** (the trims, the idle gate, the wallpaper's cover and plane):
  owner, 2026-11-19, work that only helps the current UI. Not taken up after.
- **The gated pilot and the freeze of dev**: K4 and K7 (2026-11-20).
- **The `.ui` format** and its error codes F01 to F08 (reserved, never
  raised): K1.
- **The Python reference engine and the Lua replay**: K13.
- **The designed contract entries** (`6cedcdc8d`, 2026-11-24): `page`'s
  `unit` and `nav`, `scroll new=`, `toast anchor=`, the `tool` kind,
  `cells`' `face` and `slide`, `dialog default=`, `popover` and `pane`
  `unit=`, the canvas's `size`, `sized`, `capture`, `text`, `actions` and
  `on`, `takes=` `row+arg` and `key`, the roles `menu` and `space`, and the
  verbs `unit`, `damage` and `load`. The table is add-only: a name returns
  when an engine builds it.
- **Revision 3's `"ui": N` in the manifest** (D06, reserved): the console
  API level replaced it (§17).
- **The spec's Part 2, the shell's vocabulary** (windows as rows of a model,
  the three placement rules, `shell.*`, Y01 to Y06 reserved): it waited on
  the window manager's move, which did not happen in full.
- **Old themes' title and button drawing** (K14) and the theme keys `frame`
  and `surfaces` (K16): deleted; the themes are #247.
- **#66's Python-only drag change for the S3 boards** (revision 2's decision
  13): thrown away by the sweep, as revision 2 said it would be.
- **Fold F's thin fronts**: the prop check went to C; the other checks
  (types, models, focus, the build's rules) stayed in each front, and both
  fronts grew rather than shrinking by half as estimated. No commit records
  a decision to stop; the clean cut went ahead before it.
